## Signing hierarchy

1. **Preferred:** browser Freighter via `stellar-wallets-kit` `signAuthEntry`
   (secret never leaves the wallet).
2. **Fallback (this CLI path):** local ed25519 from `.env` via stellar-cli.
   The CLI **always** prints `signing: local-signer-fallback` and the reason
   string. Never claim Freighter signed when the fallback ran.

### [BLOCKER] Freighter interactive step

When using Freighter, the human must confirm the wallet popup for each
`add_context_rule` auth entry. Headless agents use the local-signer fallback.

## Commands

```bash
# 1. Create OZ smart account (Delegated G signer)
npm run cli -- account:create --network testnet

# 2. Synthesize (or use committed examples/live/context-rule.json)
npm run cli -- synth --input examples/live/recorded-claim-swap.json

# 3. Install (simulate then submit)
npm run cli -- install \
  --smart-account CAXBVHXP4QCWFNWW223JC6DAZHRXDUS5NDRSZMFSEYKCX4C3C5U4ERXT \
  --context-rule examples/live/context-rule.json \
  --frequency-policy CDSVPSTSKMJ2EEP4FOJ3NNIJZY5DKVA3VV5BM453AOYIWCLD4NMG2ZPP \
  --spending-limit-policy <C… spending-limit wrapper> \
  --signer <G…> \
  --network testnet

# 4. Live verify
npm run cli -- verify \
  --context-rule out/installed-context-rule.json \
  --smart-account CAXBVHXP4QCWFNWW223JC6DAZHRXDUS5NDRSZMFSEYKCX4C3C5U4ERXT \
  --frequency-policy CDSVPSTSKMJ2EEP4FOJ3NNIJZY5DKVA3VV5BM453AOYIWCLD4NMG2ZPP \
  --network testnet
```

Useful flags: `--dry-run` (simulate only), `--only pw:swap,pw:harvest`
(subset). Install recomputes `validUntilLedger` from the live ledger head.

## MCP

Exactly four tools (`record` / `synthesize` / `simulate` / `verify`).
**Never** `install`. MCP `verify` may pass `smartAccount` for the same live
fetch library the CLI uses.
